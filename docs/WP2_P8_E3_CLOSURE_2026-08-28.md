## Experiment design

Three independent near-threshold ascent cycles, each:

`0 -> 49 -> 50 -> 51 -> 52 -> 0 dB`

At each 49/50/51/52 dB point:

- 20 UE->CORE ICMP probes
- 20 MQTT application messages
- continuous CORE->UE monitoring
- no `srsue`, EPC, eNB, or broker restart

## Interpretation

The qualitative threshold structure is repeatable while severity near the boundary is stochastic rather than deterministic at a single attenuation value:

- `49 dB`: consistently healthy in all three cycles.
- `50 dB`: threshold edge; 0-5% ICMP loss with complete MQTT delivery in all three cycles.
- `51 dB`: variable degraded regime; ICMP loss 5-50%, while MQTT remained 19-20/20 with hundreds-of-ms latency inflation.
- `52 dB`: consistently severe; ICMP loss 65-80% and MQTT completeness fell to 5-12/20 with multi-second and tens-of-seconds delays among delivered messages.
- RF-only restoration to `0 dB` produced autonomous recovery after every cycle without service restart.

This supports a cross-layer finding already suggested by E1/E2: network degradation precedes application completeness loss, while application latency inflates before message loss becomes dominant.

Scientific claim boundary: this is controlled POWDER manual reference evidence, not scored P7B and not yet a publication-level probabilistic characterization.
