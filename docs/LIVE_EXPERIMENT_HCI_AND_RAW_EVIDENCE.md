# WellPulse Live Experiment HCI and Raw-Evidence Architecture

**Status:** mandatory design requirement before the next POWDER Golden reservation  
**Purpose:** let the PI follow the experiment clearly in real time without contaminating the scientific run, while preserving complete raw evidence independently of the HCI.

## 1. Separation of planes

The experiment must use two strictly separated planes.

### A. Scientific Raw-Data Plane

This is authoritative scientific evidence. It must remain lossless, append-only during acquisition where practical, and independent of the display layer.

At minimum preserve:

- sender generated telemetry/raw records;
- sender queue/database state needed for reconstruction;
- MQTT publish/PUBACK event stream;
- receiver raw received records and receive events;
- RF attenuation timeline emitted by the experiment controller;
- LTE/EPC/eNB/UE logs required for substrate chronology;
- runtime/version fingerprints;
- profile revision, hardware/node bindings, experiment UUID and code commit;
- gate/event chronology;
- reconstruction inputs and resulting derived endpoint files;
- evidence manifests and SHA-256 hashes.

The HCI must never be the only location containing any scientific observation.

### B. Human-Computer Interaction / Display Plane

The HCI is a non-authoritative observer. It may display only status/telemetry already emitted by the orchestrator and workload processes as part of their normal execution.

It must not independently query, probe, restart, reconfigure, attenuate, teardown, or otherwise interact with POWDER during the protected scientific window.

`HCI_CONTROL_ACTIONS_ENABLED=false`

## 2. HCI interaction rule

During G3-G10, the HCI must consume a one-way status stream generated by the experiment itself.

Preferred architecture:

`experiment processes -> orchestrator status events -> one-way stdout/status stream -> GitHub Actions live view / future cockpit renderer`

Not allowed:

`HCI -> SSH/API/tmcc/live probe -> experiment`

No HCI refresh action may create a new POWDER command.

## 3. Minimal Experiment Cockpit

The PI-facing display should remain simple and show only information needed to understand progress and safety.

### Header

- experiment name and UUID;
- run ID;
- NON-SCORED / SCORED badge;
- exact code commit;
- reservation hard-expiry and remaining safe-run budget;
- hardware/profile identity status.

### Main progress

- G0-G10 progression bar;
- current gate name;
- elapsed run time;
- current phase: PREP / BASELINE / RF OUTAGE / RESTORE / SERVICE READY / APPLICATION HORIZON / RECONSTRUCTION / ESCROW / COMPLETE;
- latest gate PASS/FAIL and timestamp.

### Scientific-process counters

Counters may be displayed only when emitted by the sender/receiver themselves, without independent polling:

- generated records;
- publish calls;
- PUBACK callbacks;
- receiver records;
- durable/pending count when already maintained by the workload;
- current experiment clock markers such as `t_rf_restore` and `t_service_ready`.

These are live convenience indicators, not final scientific results.

### Safety panel

Always visible:

- `scored_run` status;
- independent probes: ENABLED/DISABLED;
- compatibility gate state;
- evidence-escrow state;
- persistent-copy state;
- off-POWDER copy state;
- teardown authorization;
- fail-close status.

### Raw-evidence panel

Show presence/progress only, not transformed replacements for the raw files:

- sender raw bundle: ACTIVE/FROZEN/HASHED;
- receiver raw bundle: ACTIVE/FROZEN/HASHED;
- substrate logs: ACTIVE/FROZEN/HASHED;
- `/proj/WellPulse` copy: NOT STARTED/CHECKPOINTED/VERIFIED;
- off-POWDER copy: NOT STARTED/COPIED/READ-BACK VERIFIED;
- final manifest: PENDING/PASS.

## 4. Machine-readable HCI event contract

The orchestrator should emit a minimal event stream such as:

`hci_events.jsonl`

Each event should contain only bounded non-secret fields, for example:

- UTC timestamp;
- run ID;
- gate;
- phase;
- status;
- progress percentage;
- safe counters explicitly emitted by the workload;
- reservation remaining budget if known from frozen launch metadata;
- evidence state;
- fail-close/teardown authorization state.

Do not include credentials, private keys, tokens, certificate private material, TLS session secrets, or raw payload contents in the HCI stream.

The same events should be mirrored to orchestrator stdout so GitHub Actions itself provides a usable live fallback HCI even if a richer renderer is unavailable.

## 5. Raw-data preservation policy

Raw data remains mandatory even when the HCI shows a successful run.

### During acquisition

- write authoritative raw artifacts to the qualified node-local experiment path;
- use deterministic filenames and run identity;
- never rewrite raw records for presentation;
- HCI-derived counters/status live in separate files/directories.

### Persistent staging during the run

Before the next reservation, benchmark whether checkpoint copying to `/proj/WellPulse` changes experiment timing/load materially.

If a bounded checkpoint strategy is demonstrated non-perturbing, perform orchestrator-owned checkpoints at qualified phase boundaries.

If checkpoint I/O is not demonstrated non-perturbing, do not copy during the protected scientific interval; instead reserve sufficient post-G7 time for immediate freeze/hash/escrow before expiry.

No independent background sync is allowed until qualified by the compatibility gate.

### Final freeze and escrow

Before teardown:

1. stop/freeze writers in the defined order;
2. inventory mandatory raw artifacts and require non-empty files where expected;
3. compute source SHA-256 manifest;
4. copy complete bundle to `/proj/WellPulse/evidence-escrow/<experiment>/<run-id>/`;
5. verify the persistent copy against the source manifest;
6. copy the same verified bundle off POWDER to the approved external evidence store;
7. perform read-back/hash verification;
8. record UUID/profile/hardware/code/runtime/evidence locations and hashes in the canonical repository;
9. only then allow teardown.

Required outputs:

`RAW_EVIDENCE_COMPLETE=PASS`

`EVIDENCE_ESCROW_GATE=PASS`

`TEARDOWN_AUTHORIZED=YES`

## 6. Acceptance tests before reservation

The next Golden may be booked only after all of the following pass offline or in a bounded non-scientific smoke environment:

1. HCI events are generated from orchestrator/process state without new POWDER probes.
2. GitHub Actions live output renders the gate/phase/progress/safety information clearly.
3. HCI failure cannot stop, alter, or invalidate the scientific run.
4. HCI cannot issue control commands.
5. Raw files are byte-for-byte independent of HCI summaries.
6. Required raw-artifact inventory is complete.
7. Freeze/hash/persistent-copy/off-platform-copy/read-back verification works end to end.
8. Any proposed in-run `/proj` checkpoint method is benchmarked for non-interference before authorization.
9. Reservation budgeting includes full raw-data escrow and verification time.

Required design gate:

`LIVE_HCI_AND_RAW_EVIDENCE_GATE=PASS`

Until then, the next live Golden reservation is not authorized.
